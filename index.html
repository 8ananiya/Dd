Hybrid FxLMS Controller

Architecture — strongest feasible in a browser
  • Hybrid feedforward + feedback FxLMS: two independent adaptive FIR filters. FF handles broadband reference noise; FB suppresses residual at the error mic. This is the topology Renesas DA7403 and Sony/Apple silicon use[reference:0].
  • Online secondary-path modeling (SPM): a low-level dither continuously re-identifies the speaker→mic transfer function, so the filtered-x reference stays correct if the fit or head position changes[reference:1].
  • NLMS normalization + leakage: step size scales inversely with reference power; leakage term keeps weights bounded. Together they prevent the divergence that kills naive LMS ANC.
  • Neural noise classifier: a tiny CNN (via ONNX Runtime Web / WASM) classifies the incoming noise spectrum into {steady rumble, HVAC, engine, broadband, speech-like, transient} and selects a pre-shaped filter prior. This is the browser analogue of GFANC's deep-learning weight generation — GFANC-Headphone uses a CNN co-processor that generates filter weights frame-by-frame[reference:2]. Full GFANC would require running the CNN at sample rate on dedicated silicon.
  • The hard wall: browser audio round-trip is 10–30 ms. Commercial ANC chips run at 5.2 µs (fast path) / 25 µs (DSP path)[reference:3]. At 20 ms you can cancel cleanly below ~25 Hz; at 5 µs you can reach 2.5 kHz. No algorithm closes a 1000× latency gap. This system is the real algorithm on the wrong hardware.
  • For context, the strongest published open-source ANC is WaveNet-VNNs (fully causal) and GFANC-Bayes (delayless generative fixed-filter). Both require host-side or FPGA inference[reference:4][reference:5].
